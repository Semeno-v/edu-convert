# EduConvert

**Автоматизированная конвертация рабочих программ дисциплин (РПД) и фондов оценочных средств (ФОС) в целевые шаблоны 2026 года.**

Пакетно и поодиночке переносит старые документы Word в новые официальные формы, при этом:

> **Золотое правило.** Единственный источник истины для всех чисел (зачётные единицы, академические часы, семестры, формы контроля) — это загружаемая **База данных (Excel)**. Из старых документов Word берутся **только текстовые смысловые блоки** (компетенции, тематический план, литература, оценочные средства). Старые числа используются исключительно для **отчёта о расхождениях** и никогда не попадают в новые документы.

---

## Возможности

- Пакетная обработка папки с РПД/ФОС в форматах `.docx` и устаревшем `.doc`.
- Извлечение эталонных чисел из листа **«План»** учебного плана (polars + fastexcel) **по ключевым словам шапки**, а не по жёстким индексам ячеек — устойчиво к сдвигам колонок и блокам семестров.
- Извлечение текстовых блоков из старых документов **конечным автоматом** по заголовкам (с сохранением форматирования: списков, жирного шрифта, таблиц).
- Генерация целевых документов через `docxtpl` (числа из Базы, текст из исходников).
- **Жёлтая заливка всего заполненного конвертацией** (часы, компетенции, литература, тематический план, оценивание); статичные разделы шаблона остаются без заливки — соответствует одобренному эталонному формату.
- **§2 «Планируемые результаты»** строится из Базы (лист «Компетенции», код→текст) как текстовые абзацы; **§4 «Литература»** — нумерованный список «Автор. Название. Выходные данные. URL» из таблицы исходника; **§8** — родительские коды компетенций (ПК-1, ПК-2).
- Отчёт о расхождениях (Excel) + ZIP-архив с результатами.
- **Изоляция сбоев:** ошибка одного файла не прерывает обработку остальных.
- Декларативный интерфейс на Flet 0.85 (Material Design 3) с реактивным прогрессом; асинхронный оркестратор на FastAPI с изоляцией блокирующих вызовов в пуле потоков.

## Требования

- **Python 3.14+**
- **Microsoft Word** (Windows) — нужен только для конвертации устаревшего `.doc` (через COM/`pywin32`). Для `.docx` не требуется.

## Установка

```powershell
py -3.14 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Быстрый старт на синтетическом примере

Чтобы проверить работу без реальных данных вуза, есть синтетический набор в `samples/`:

```powershell
python -m app.cli --db "samples/план_пример.xlsx" --input samples --out пример.zip
```

Пример специально содержит расхождение (старые лекции 16 ≠ 12 по плану), поэтому
в `report.xlsx` будет строка-расхождение, а в документ запишутся числа из плана.
Пересоздать пример: `python -m tools.make_sample`.

## Подготовка шаблонов

Размеченные тегами `docxtpl` шаблоны лежат в `templates/`:

- `templates/rpd_2026_tagged.docx`
- `templates/fos_2026_tagged.docx`

Они получены из официальных пустых форм 2026 года скриптом `tools/build_templates.py`
(редакторские подписи заменены на теги `{{ }}`, пустые ячейки таблицы часов — на
`{{ hours_* }}`, стандартные пред-заполненные разделы оставлены без изменений).
Чтобы перегенерировать из своих форм:

```powershell
python -m tools.build_templates --rpd-src "Шаблон РП (2026).docx" --fos-src "ФОС_ШАБЛОН (2026).docx"
```

## Запуск

### CLI (пакетный прогон без интерфейса)

```powershell
python -m app.cli --db "база.xlsx" --input <папка-или-файлы> --out результат.zip
```

Пример с конкретными файлами:

```powershell
python -m app.cli --db "база.xlsx" --input Б1_О_01_РПД.docx ФОС_Б1_О_01.docx --out результат.zip
```

### Веб-интерфейс (FastAPI + Flet)

```powershell
uvicorn app.main:app --port 8000
# открыть http://127.0.0.1:8000  — UI;  /health — служебный эндпоинт
```

### Настольное приложение (Flet)

```powershell
python -m app.ui.main_view
```

> **О выборе файлов.** Исходные документы и базовые файлы выбираются кнопками
> «Выбрать файлы» / «Выбрать папку» (системный `FilePicker`) — это предусмотренная
> ТЗ §5 альтернатива зоне drag&drop (нативный OS-drop в Flet на Windows
> поддерживается ограниченно).

## Структура проекта

```
app/
├── main.py                 # FastAPI + маунтинг Flet
├── cli.py                  # CLI-прогон
├── config.py               # настройки (пути, теги, листы)
├── core/                   # бизнес-логика (не зависит от UI)
│   ├── interfaces.py       # Protocol-интерфейсы слоёв
│   ├── models.py           # Pydantic-схемы (+ сериализуемый IR контента)
│   ├── normalizer.py       # нормализация текста/индексов/чисел
│   ├── exceptions.py       # кастомные исключения
│   ├── excel_parser.py     # чтение листа «План» (polars + fastexcel)
│   ├── doc_converter.py    # .doc → .docx (MS Word COM)
│   ├── word_extractor.py   # конечный автомат чтения старых docx
│   ├── word_generator.py   # рендеринг docxtpl (RichText / subdoc)
│   └── differ.py           # сравнение старых чисел с эталоном
├── services/
│   └── orchestrator.py     # асинхронный ETL-оркестратор
└── ui/                     # Flet (декларативный подход)
    ├── main_view.py        # AppState (@ft.observable) + App (@ft.component)
    └── components/         # upload_card, report_table
templates/                  # размеченные шаблоны 2026
tools/build_templates.py    # разметка шаблонов тегами
tests/                      # pytest (синтетические фикстуры)
```

## Архитектура и принципы

- **Слой `core/`** не зависит от UI и транспорта; экстракторы/генераторы скрыты за
  `Protocol`-интерфейсами — слой можно переписать (в т.ч. на Go/Rust), не меняя
  оркестратор. Данные между слоями передаются только Pydantic-моделями.
- **Числа vs текст.** Текстовый контент представлен сериализуемым IR
  (`RichRun → RichParagraph → RichTable → ContentBlock`), независимым от python-docx.
- **Асинхронность.** Тяжёлые операции (чтение/запись docx, конвертация `.doc`,
  чтение Excel, архивирование) выполняются в пуле потоков, не блокируя event loop.

## Данные и приватность

Реальный учебный план (`база.xlsx`) и исходные РПД/ФОС **исключены** из репозитория
(`.gitignore`), так как содержат внутренние сведения вуза. Тесты используют
синтетические фикстуры и не требуют реальных данных.
